5. THE 32/64 QUESTION (explicitly)
================================================================================
external/xnu-hd2-darwin13/xnu/osfmk/mach/arm/vm_types.h:107-109 make mach_vm_address_t /
mach_vm_size_t **32-bit** ("We target iOS 4.3 for compatibility").

- The REAL client's addr word is r1 = a 32-bit &address (the wrapper's `mov r1,sl` with sl loaded
  from a 4-byte slot). The frame slot 2 (r2) is `size`, NOT the high half of a 64-bit address.
- The handler's `copyin(regs[1], &address64, sizeof(address64))` (mach_kernelrpc.c:222) read
  EIGHT bytes: slots 1 AND 2. Slot 2 is the SIZE (0x1000). On little-endian that yields
  address64 = (0x1000 << 32) | *(&address). If *(&address)=0x1000 (the caller's seed), address64 =
  0x0000100000001000, and the :224 guard `(address64 >> 32)` != 0 => KERN_INVALID_ARGUMENT
  IMMEDIATELY, before mach_vm_map is even called.
  => INCONSISTENT. The existing handler's 64-bit copyin of the slot-1 address CONTRADICTS the
     client's 32-bit &address and DOES misread the frame relationship between slots 1 and 2.
  => This is the real trap-15 wire defect, and it is INDEPENDENT of §4: fixing §5 alone
     (copyin 4 bytes at regs[1], drop the `address64>>32` test) is necessary for the fast call.

  # These two fixes together = "open the -15 row" is NOT sufficient. Owed wire changes:
  #   (a) mach_kernelrpc.c:222 — copyin sizeof(mach_vm_address_t)=4, not 8;
  #   (b) mach_kernelrpc.c:224 — drop the `address64 >> 32` test (native 32); re-examine the
  #       `regs[5]` guard against the client's actual slot 5 (the wrapper puts the size buffer
  #       there — # UNMEASURED);
  #   (c) mach_kernelrpc.c:229 — protection is NOT regs[8]; REGS[8] HOLDS THE TASK PORT. Use
  #       VM_PROT_ALL (safe: the client's os_alloc maps RW) or resolve the 7th wire word.
  #   (d) syscall_sw.c:126-129 — the IOS7_COMPAT_PLATFORM gate must also open for CANCRO.
  # UNMEASURED: which C arg the wrapper's stack words map to, hence the exact value the client
  # intends as `protection`. Its guard (`[r7,20]==0 && [r7,40]==7 && [r7,44]==1`) did NOT reject

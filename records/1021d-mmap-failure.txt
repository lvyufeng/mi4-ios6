6. THE COMPETING CANDIDATE I CANNOT CLOSE — the ARM superpage default (KERN_INVALID_ARGUMENT)
====================================================================================================
§1(3) is not decoration: on armv7 the `VM_FLAGS_SUPERPAGE_MASK` bit set means the switch falls to
`default: return KERN_INVALID_ARGUMENT` — the ONLY `case` labels are `#ifdef __x86_64__`. I verified
this fence is present in OUR tree, in `external/xnu-4570.1.46` and in `external/xnu-2050.18.24`
(three independent reads), and the LINKED image agrees (`vm_map_enter` 0x8003e7cc/0x8003f018, r6=4).
**AND I THEN CHECKED THE RUNG'S OWN OBJECT — this is no longer inference.** `arm-none-eabi-objdump
-d out/xnu_kernel_obj_d13/osfmk_vm_vm_map.o`:
    fec: e3a00004  mov  r0, #4                 ; KERN_INVALID_ARGUMENT, set BEFORE the test
    ff8: e3180807  tst  r8, #458752 ; 0x70000 ; flags & VM_FLAGS_SUPERPAGE_MASK
    ffc: 1a0001c9  bne  1728 <vm_map_enter+0x750>
    1728: e28dd074 add sp, #116 ; e8bd8ff0 pop {r4-r9,sl,fp,pc}   ; the EPILOGUE, returns r0 = 4
(and the linked image's mirror: 0x8003e7c0 `mov r6,#4`, 0x8003e7cc `tst r1,#0x70000`,
0x8003e7d0 `bne 8003f018`, 0x8003f018 `mov r0,r6` + epilogue.) So THIS rung returns **4** for any
`flags & 0x70000 != 0` — CONFIRMED BY VALUE, not read off the source alone.
So `__os_alloc_slow`'s own flags word `0x49000001` would ask for an ARM-unsupported superpage-ANY and
get **4** back — i.e. the map would fail on EVERY ARM device, for every libsystem_platform slow alloc.
That is implausible as the silent truth of iOS 7, which means in one of two places my decode of the
flag word or the ARM build's behaviour is off:
  (i) the flags slot the wrapper forwards is not literally 0x49000001 (the wrapper re-frames the
      caller's words — the 6-word `ldm ip,{r4,r5,r6,r8}` at the fast stub forwards caller words, and
      the MIG shim's slot mapping at [r7,#20]/[r7,#24]/... can scramble which word lands in
      `mach_vm_map`'s `flags` argument); or
  (ii) this arm's vm_map.c build actually compiles SUPERPAGE_SIZE_ANY on ARM (e.g. a local patch or
      a wider `#if`), in which case 0x10000 is benign and §5 stands alone.
The capture's r0 = 0x103 low byte = 3 flips the balance toward **(ii) + KERN_NO_SPACE** rather than
(i)+4, but I cannot prove the argument wiring statically (the decoder is 3 frames deep in the
shared cache and the MIG demux is a hook). **This is the single largest hole in the record.**

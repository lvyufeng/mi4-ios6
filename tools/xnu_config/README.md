# `tools/xnu_config/` — Apple's own kernel configuration machinery

## The correction this directory exists for

For several sessions this project recorded, in the roadmap and in commit messages, that **"the
build configuration is absent"** — that `osfmk/conf/MASTER.XXX` is named by
`osfmk/kern/sched_prim.h:574`'s `#error` but is not in the tarball, that `MAKE.XXX` and the
per-arch target definitions are generated by a build system Apple did not ship, and that the
kernel's configuration therefore had to be guessed at one value at a time.

**That is wrong.** The files are in the tarball:

| What | Where |
| --- | --- |
| Master configuration | `config/MASTER` (737 lines) |
| ARM master | `config/MASTER.arm` (86 lines) |
| The configuration tool's source | `SETUP/config/{main.c,parser.y,lexer.l,mkheaders.c,mkmakefile.c,…}` |
| The driver script | `SETUP/config/doconf` |

`osfmk/conf/MASTER.XXX` is where doconf **writes** its output, not where the source lives. The
search that concluded "absent" looked in `osfmk/conf/` — the directory the error message names —
and did not look at the repository root, where `config/` has been sitting the whole time.

## What it gives you

`config/MASTER.arm` states the ARM kernel's attribute sets in Apple's own words:

```
KERNEL_BASE = [ arm xsmall config_embedded ]
SCHED_BASE  = [ config_sched_traditional config_sched_multiq ]
MACH_BASE   = [ mach slidable vc_progress_white mdebug ipc_debug importance_inheritance
                config_atm config_coalitions config_library_validation config_iosched
                config_telemetry config_sysdiagnose ]
BSD_BASE    = [ mach_bsd config_workqueue psynch config_proc_uuid_policy ]
SECURITY    = [ config_macf ]
```

and `expand.sh KERNEL_BASE` resolves those recursively into the **option lines** the kernel is
built with — concrete values, including several this project had been guessing at:

```
options   CONFIG_ZONE_MAP_MIN=1048576
options   CONFIG_TASK_MAX=512
options   CONFIG_IPC_TABLE_ENTRIES_STEPS=64
options   CONFIG_MAX_CLUSTERS=4
options   CONFIG_MAX_THREADS=64
options   CONFIG_ZONE_MAP_MIN=1048576
options		SERIAL_CONSOLE
options		VIDEO_CONSOLE
```

Three of those — `CONFIG_ZONE_MAP_MIN`, `CONFIG_TASK_MAX`, `CONFIG_IPC_TABLE_ENTRIES_STEPS` —
appeared in this project's own osfmk sweep as *undeclared identifiers*. They were never missing.
They were being looked for in the wrong place.

`sched_group_t`, the largest single blocker in that sweep at 25 occurrences, is gated on
`CONFIG_SCHED_MULTIQ` — which `SCHED_BASE` says is **on**.

## How to use it

```bash
./tools/xnu_config/expand.sh KERNEL_BASE        # the option lines for an ARM kernel
./tools/xnu_config/select_master.sh KERNEL_BASE # the attribute-selected master lines
```

Both are bash ports of `doconf`'s two stages: `select_master.sh` is its sed pipeline, and
`expand.sh` is its awk expansion. `doconf` itself is a `csh` script and this host has no `csh`; the
pipeline is the same either way.

`SETUP/config` also builds as a host tool — bison, flex and eight small C files with
`-DYY_NO_INPUT`, no XNU build system needed. That is the next step: doconf generates
`osfmk/conf/MASTER.XXX`, and the `config` binary generates the headers (`config.h`, and
`mkheaders.c`'s output) that `MakeInc.*` consumes.

## The pattern worth remembering

This is the **third** time in this project that "it is not available" turned out to mean "I looked
in one directory":

1. MIG — "not in the tarball and not in this host's package repository" — was published at
   `apple-oss-distributions/bootstrap_cmds`. Two turns of MIG output came out of that.
2. The generated mach headers — "40 `.defs` ship and their headers do not" — were a *build step*
   away, not a wall.
3. This one: the configuration — "absent" — is at `config/` and `SETUP/config/`.

Each time the fix was the same: search the whole tree for the *shape* of the thing (a `.defs`, a
`MASTER.*`, a tool's source) rather than concluding from the path an error message happened to
name. A missing file at one path is not a missing file.
